# 指纹匹配算法说明

## 1. 文档目的

本文档说明当前这套基于 `.mnt` 细节点文件的 `1:1` 指纹验证算法，包括：

- 算法整体流程
- 各模块职责
- 多模板匹配策略
- FAR / FRR / EER 的计算方式
- 如何运行脚本
- 输出结果如何理解

当前实现的目标是：在不依赖原始指纹图像、只使用细节点文本文件的前提下，构建一套可运行、可调参、偏向低 `FAR` 的验证算法。

## 2. 输入数据假设

当前程序默认输入目录为：

`leader-minutiae/minutiae`

并假定目录结构形如：

```text
leader-minutiae/minutiae/
  zyh_R0/
    Rgd1237/
      zyh_R0_pair0.mnt
      zyh_R0_pair1.mnt
      ...
  zyh_R1/
    Rgd1237/
      zyh_R1_pair0.mnt
  zyh_R2/
    Rgd1237/
      zyh_R2_pair0.mnt
```

程序会自动推断：

- `subject`：如 `zyh`
- `session`：如 `R0`、`R1`、`R2`
- `group_id`：如 `Rgd1237`
- `sample_index`：如 `pair99` 中的 `99`

单个 `.mnt` 文件默认格式为：

```text
12
85 5 2.379009 B
87 13 -0.775504 E
...
```

含义为：

- 第一行：细节点总数
- 后续每行：`x y angle type`
- `type` 当前仅支持 `B` 和 `E`

## 3. 算法总体流程

整套算法分为五步。

### 3.1 数据解析与标准化

对应文件：`matcher/io.py`

主要工作：

- 读取 `.mnt` 文件
- 解析细节点文本
- 把角度统一规整到 `[-pi, pi]`
- 去掉格式异常和非法类型记录
- 对明显重复的细节点做轻量去重
- 自动跳过 `0` 细节点或无有效细节点的坏样本，避免评测中断

此外，这一层还负责根据目录结构自动构建身份信息，并生成：

- 注册样本池 `enrollment_pool`
- 开发集 `dev_probes`
- 测试集 `test_probes`

默认划分规则是：

- `R0` 作为注册集
- `R1` 作为开发集
- `R2` 作为测试集

如果某些身份不满足三轮数据，则退化为比例切分。

### 3.2 单模板细节点匹配

对应文件：`matcher/core.py`

这是核心匹配模块，输入是一张模板和一张待测样本，输出一个匹配分数。

流程如下：

1. 计算每个细节点的局部支撑强度
2. 在模板和探测样本中各选一批锚点候选
3. 遍历锚点对，估计旋转量
4. 将探测样本旋转、平移到模板坐标系
5. 在对齐后做一对一贪心配对
6. 根据匹配数量、覆盖率、距离误差、角度误差生成最终分数

#### 3.2.1 为什么要选锚点

细节点匹配的难点在于两张指纹之间往往存在：

- 平移
- 旋转
- 局部缺失
- 虚假细节点

所以不能直接按坐标逐点比较。当前实现通过“锚点对齐”先粗略估计空间变换，再在统一坐标系里做细匹配。

#### 3.2.2 局部支撑强度

算法会统计某个细节点周围一定半径内的邻居数量和距离分布。

直觉上：

- 周围邻居更多的点更稳定
- 处于稀疏边缘的点更容易受截断影响

因此更适合作为锚点的细节点，会优先被纳入候选。

#### 3.2.3 一对一贪心配对

对齐完成后，程序会为所有满足约束的模板点和探测点建立候选匹配对，约束包括：

- 类型相同
- 距离误差不超过阈值
- 方向误差不超过阈值

然后按照代价从小到大贪心选择，确保：

- 每个模板点最多匹配一次
- 每个探测点最多匹配一次

这是一个计算量较低、实现稳定的近似一对一匹配方法。

#### 3.2.4 方向误差中的 180 度翻转处理

部分细节点方向存在 180 度对称歧义，所以程序同时比较：

- 原始方向差
- 加上 `pi` 后的方向差

并取两者较小值作为有效方向误差。

这样可以减少由于方向定义差异导致的误拒。

### 3.3 多模板融合

对应文件：`matcher/fusion.py`

单张模板容易受到单次采集噪声影响，因此系统支持一个身份使用多张模板。

流程是：

1. 从注册池中按质量代理分数挑选前 `N` 张模板
2. 每张模板分别与探测样本做一次匹配
3. 对多个单模板分数进行融合

当前支持的融合方式：

- `max`
- `mean`
- `median`
- `trimmed_mean`
- `harmonic_mean`

其中：

- `max` 更激进，容易产生较高假接受
- `mean`、`median` 更稳健
- `harmonic_mean` 更保守，更适合低 `FAR` 目标

### 3.4 开发集自动调参

对应文件：`matcher/eval.py`

系统会在开发集上自动搜索以下参数：

- 模板张数 `template_count`
- 空间容差 `distance_tolerance`
- 角度容差 `angle_tolerance`
- 最小匹配数 `min_matches`
- 分数融合方式 `fusion_method`

搜索目标不是单纯最小 `EER`，而是：

`weight_far * FAR + FRR`

也就是对 `FAR` 给更大惩罚，使得最终配置更加保守，符合“优先压低 FAR”的要求。

### 3.5 测试集评估

开发集上选出的最佳参数和阈值，会固定后应用到测试集。

程序会输出：

- `FAR`
- `FRR`
- `EER`
- 推荐阈值
- 若干低 `FAR` 工作点
- 下采样后的 `DET` 曲线点

## 4. 评分与指标解释

### 4.1 genuine 分数

模板身份与探测身份相同时得到的分数，称为 genuine 分数。

这类分数越高越好。

### 4.2 impostor 分数

模板身份与探测身份不同时得到的分数，称为 impostor 分数。

这类分数越低越好。

### 4.3 FAR

`False Accept Rate`

当模板和探测样本属于不同身份时，却被系统错误接受的比例。

这个值越低越好。

### 4.4 FRR

`False Reject Rate`

当模板和探测样本属于同一身份时，却被系统错误拒绝的比例。

这个值越低越好。

### 4.5 EER

`Equal Error Rate`

FAR 与 FRR 最接近时的误差率近似值，用于概括系统整体区分能力。

### 4.6 为什么本实现更偏向低 FAR

当前任务明确要求优先压低 FAR，所以本实现采用了三层保守策略：

- 调参目标对 FAR 赋予更高权重
- 多模板可选保守融合方式
- 文档输出额外给出多个低 FAR 工作点

这意味着某些配置下 `FRR` 可能略高，但能换取更低的误识风险。

## 5. 代码结构说明

### `matcher/io.py`

负责：

- 读取 `.mnt`
- 解析路径
- 构建样本索引
- 生成身份划分

### `matcher/core.py`

负责：

- 单模板匹配
- 锚点对齐
- 一对一贪心配对
- 生成单模板分数

### `matcher/fusion.py`

负责：

- 模板筛选
- 多模板分数融合

### `matcher/eval.py`

负责：

- 参数搜索
- 阈值搜索
- genuine / impostor 分数统计
- FAR / FRR / EER 计算

### `run_verification.py`

负责：

- 命令行参数入口
- 执行整套流程
- 输出 JSON 报告

## 6. 如何运行

下面给出默认运行方式。

```bash
python run_verification.py
```

默认等价于：

```bash
python run_verification.py --root leader-minutiae/minutiae --output verification_report.json
```

如果想手动指定搜索空间，可以这样运行：

```bash
python run_verification.py \
  --root leader-minutiae/minutiae \
  --output outputs/report.json \
  --template-counts 1,3,5,8 \
  --distance-tolerances 10,12,14 \
  --angle-tolerances 0.35,0.5,0.65 \
  --min-matches 5,6,7 \
  --fusion-methods mean,median,harmonic_mean \
  --weight-far 12
```

参数说明：

- `--root`：`.mnt` 数据根目录
- `--output`：结果 JSON 输出路径
- `--template-counts`：待搜索模板数集合
- `--distance-tolerances`：空间容差集合
- `--angle-tolerances`：角度容差集合
- `--min-matches`：最小匹配数集合
- `--fusion-methods`：融合方式集合
- `--weight-far`：开发集上 FAR 惩罚权重

## 7. 输出结果说明

输出 JSON 中主要字段包括：

- `identity_count`：身份总数
- `selected_template_count`：自动选择的模板张数
- `selected_fusion_method`：自动选择的融合方式
- `selected_threshold`：最终使用的决策阈值
- `selected_match_parameters`：匹配参数
- `dev_metrics`：开发集结果
- `test_metrics`：测试集结果

其中 `dev_metrics` 和 `test_metrics` 内通常包含：

- `far`
- `frr`
- `eer`
- `genuine_score_mean`
- `impostor_score_mean`
- `low_far_points`
- `det_curve`

## 8. 当前实现的特点与局限

### 优点

- 完全基于细节点文本，不依赖原始图像
- 支持多模板验证
- 自动搜索模板数与匹配参数
- 目标函数偏向低 FAR，适合保守验证场景
- 输出结构化 JSON，方便后续分析

### 局限

- 当前没有使用原图中的纹线流、区域质量图、细节点置信度等更强特征
- 当前对齐策略是锚点驱动的近似方法，不是全局最优图匹配
- 质量代理分数是启发式的，不是真实采集质量标签
- 当前目录标签推断依赖现有命名规则

## 9. 后续可优化方向

如果后续要继续降低 FAR / FRR，可以考虑：

1. 引入更强的局部结构描述子，而不只使用坐标与方向
2. 加入基于邻接图或三角结构的几何一致性评分
3. 使用更精细的模板融合策略，例如加权融合
4. 使用专门的阈值开发集，避免开发集与测试集分布耦合
5. 如果能补充论文 PDF 中的关键细节，再进一步向 LEADER 的具体设计靠拢
